# Dataset inventory and provenance

`new_weather_data.csv` is the input for the supported next-day benchmark. It contains 3,655 records: one daily record for each of five cities from 2023-01-01 through 2024-12-31. The required fields are `Date_Time`, `City`, and `Temperature_C`. There are no missing required values or city/date gaps. Optional precipitation and pressure fields contain 19 and 10 missing values respectively; the current forecast does not use them.

**Provenance is unverified.** The repository does not establish the original provider, station identifiers, collection method, timezone, whether `Temperature_C` is a mean or point reading, licensing, or how new rows should be obtained. The benchmark is useful for testing the pipeline but does not establish live forecasting skill. The bundled series ends in 2024, so its next-day prediction is a historical estimate.

The [historical source review](../docs/DATA_SOURCE_REVIEW.md) compares candidate providers for a future three-target dataset and includes a reproducible coverage probe. Its successful API check does not establish the source or license of `new_weather_data.csv`.

`era5_five_cities.csv` is a **separate, attributed research dataset** from Open-Meteo's ECMWF ERA5 historical API, retrieved for 2020-01-01 through 2025-12-31. It contains 10,960 city-days with `Date`, `City`, `Mean_C`, `Min_C`, and `Max_C`; `era5_five_cities.metadata.json` records source, retrieval time, coordinates, license, coverage, and SHA-256. Run `python -m scripts.build_era5_dataset --start 2020-01-01 --end 2025-12-31 --out data/era5_five_cities.csv` to retrieve a new snapshot. Open-Meteo API data requires CC BY 4.0 attribution; credit Open-Meteo and ECMWF/Copernicus ERA5 when reusing this transformed CSV. ERA5 is reanalysis, not station observation. See the [technical report](../docs/PROJECT_REVIEW_FA.md) for the evaluation scope and limits.

`era5_utc_five_cities.csv` is a **different GMT-day snapshot** of the same five
ERA5 grid points and dates, with matching schema and its own provenance manifest.
It exists solely to compare forecasts with NOAA SSODv2's 00–23 UTC station day;
do not mix it with `era5_five_cities.csv` or label it as an Iran local-day target.
Run `python -m scripts.build_era5_dataset --start 2020-01-01 --end 2025-12-31 --timezone GMT --out data/era5_utc_five_cities.csv` to request a new snapshot. See the [station validation report](../docs/SSOD_VALIDATION_FA.md). The NOAA station rows are not committed; source response hashes and aggregate metrics are in the reports.

The primary local-day station check uses quality-screened NOAA GHCNh hourly
files, aggregated to `Asia/Tehran` days and compared with `era5_five_cities.csv`.
Download them to ignored `artifacts/` with `python -m scripts.fetch_ghcnh`, then
run `python -m scripts.evaluate_ghcnh_local`. Only aggregate coverage, hashes,
and errors are committed. See the [local station report](../docs/LOCAL_STATION_VALIDATION_FA.md).

`era5_2026_five_cities.csv` extends the same local-day research source from
2026-01-01 through 2026-10-31 for a later, predeclared model check. Its manifest
records source, retrieval date, coverage, and SHA-256. The corresponding
[station report](../docs/LATER_STATION_EVALUATION_FA.md) is indeterminate because
quality-screened 2026 station coverage is insufficient; the CSV is reanalysis,
not a snapshot of forecasts issued in 2026.

Before adding observations, record the source URL or provider, location/station identifiers, temperature definition and units, timezone and daily aggregation, license, retrieval date, and any cleaning steps. Keep raw source files and retrieval metadata separate from validated model inputs. Re-run data validation and rolling backtests after each update.

For a fully reproducible synthetic input, run `python -m scripts.generate_sample_data --out artifacts/sample_weather.csv` from the repository root. It writes one row per city per day for `Sample_North` and `Sample_South` from 2023-01-01 through 2024-12-31. The CSV schema is `Date_Time` (ISO `YYYY-MM-DD` midnight date), `City` (nonempty text), and `Temperature_C` (finite Celsius number). Values are generated by the formula documented in the script and contain no real observations. Use `--data artifacts/sample_weather.csv` with the forecasting CLI, or set `TEMP_ANALYSIS_DATA` for the dashboard.

Other files (`fullweather.csv`, `kh_weather_data.csv`, `train_processed.csv`, `test_processed.csv`, and `weather_data.csv`) have different schemas or purposes. In particular, `weather_data.csv` is approximately 103 MB and has one million rows; its relationship to the five-city benchmark is undocumented. Do not combine these files until their origin, target alignment, and temporal split have been verified.
