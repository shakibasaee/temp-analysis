# گزارش فنی پروژهٔ پیش‌بینی دمای پنج شهر

**آخرین بازبینی: ۹ نوامبر ۲۰۲۶**

## هدف و وضعیت محصول

هدف مورد توافق، انتخاب یکی از پنج شهر `Bandar_Abbas`، `Mashhad`، `Rasht`، `Sanandaj` و `Yazd` و یک تاریخ از ۱ تا ۳۰ روز آینده، سپس نمایش میانگین، کمینه و بیشینهٔ دمای آن روز به درجهٔ سانتی‌گراد است. کاربرد فعلی آموزشی و غیرتجاری است. موفقیت باید هم با خطای مطلق میانگین (MAE، °C) و هم درصد پیش‌بینی‌های دارای خطای حداکثر ±۲°C سنجیده شود.

**این تجربهٔ کاربری هنوز منتشر نشده است.** برنامهٔ فعلی مخزن فقط مقدار نامشخص `Temperature_C` را برای روز بعد از آخرین رکورد CSV قدیمی تخمین می‌زند. منشأ و تعریف آن CSV روشن نیست. کار جدید یک مسیر مستقل داده و ارزیابی پژوهشی برای سه دمای روزانه ساخته است؛ عددهای این گزارش را نباید به‌عنوان دقت برنامهٔ فعلی یا پیش‌بینی زنده معرفی کرد.

## آنچه انجام شد

1. گزینه‌های منبع تاریخی از نظر سه متغیر، پوشش، زمان محلی، تازگی، مجوز و ماهیت مشاهده/بازتحلیل مقایسه شدند؛ جزئیات در [بررسی منابع](DATA_SOURCE_REVIEW.md) است.
2. دادهٔ مستقل `data/era5_five_cities.csv` از **Open-Meteo Historical Weather API با مدل صریح `era5`** برای ۲۰۲۰-۰۱-۰۱ تا ۲۰۲۵-۱۲-۳۱ دریافت شد. این فایل جایگزین CSV قدیمی نیست.
3. دستور دریافت، پنج مختصات پیشنهادی، متغیرها، واحد، منطقهٔ زمانی، زمان دریافت، شمار رکورد و SHA-256 در `data/era5_five_cities.metadata.json` ثبت شد. پیش از ارزیابی، هش و پوشش فایل با فراداده بررسی می‌شود.
4. آزمون تاریخی افق‌های ۱ تا ۳۰ روز با سه روش روی **نمونه‌های یکسان** اجرا شد: ماندگاری آخرین مقدار قابل دسترس، مقدار آخرین روز هم‌نام هفته، و رگرسیون Ridge. تبدیل ویژگی‌ها فقط روی مجموعهٔ آموزش برازش شد.
5. گزارش عددی کامل در [ERA5_EVALUATION.json](ERA5_EVALUATION.json) قرار دارد؛ برای هر شهر، افق، هدف و روش، تعداد نمونه، MAE و درصد خطای حداکثر ±۲°C ثبت شده است.

## کارت داده

| ویژگی | مقدار |
|---|---|
| ارائه‌دهنده | [Open-Meteo Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api)، دادهٔ بازتحلیل ECMWF ERA5 |
| مجوز | [شرایط Open-Meteo](https://open-meteo.com/en/terms): دادهٔ API تحت CC BY 4.0 و با الزام انتساب؛ استفاده از API رایگان برای کاربرد غیرتجاری |
| انتساب | دادهٔ هواشناسی: Open-Meteo و ECMWF/Copernicus ERA5؛ مقادیر به CSV پنج‌شهری با نام ستون‌های تازه تبدیل شده‌اند |
| پوشش | پنج نقطهٔ شهری پیشنهادی، ۲۰۲۰-۰۱-۰۱ تا ۲۰۲۵-۱۲-۳۱، برای هر شهر ۲٬۱۹۲ روز؛ جمعاً ۱۰٬۹۶۰ ردیف |
| متغیرها | `temperature_2m_mean`, `temperature_2m_min`, `temperature_2m_max` به‌ترتیب در `Mean_C`, `Min_C`, `Max_C` |
| روز و واحد | روز تقویمی `Asia/Tehran`، درجهٔ سانتی‌گراد؛ متغیرها دمای هوا در ارتفاع ۲ متر هستند |
| کنترل دریافت | برای هر شهر و متغیر صفر مقدار گمشده؛ صفر نقض رابطهٔ کمینه ≤ میانگین ≤ بیشینه؛ تاریخ‌ها پیوسته |
| هش فایل | `88c9226ad1306a3de6e63b4f027c95cf8853db05e98b5070782eba843c5e941f` |

مختصات، شناسهٔ جست‌وجوی مکانی و نقطهٔ شبکهٔ واقعی هر شهر در فراداده‌اند. این‌ها **ایستگاه هواشناسی نیستند**؛ نقطهٔ شبکه ممکن است با مرکز شهر فاصله داشته باشد. ERA5 هم تخمین بازتحلیل است، نه اندازه‌گیری مستقلِ دماسنج. [توضیح رسمی ERA5](https://cds.climate.copernicus.eu/datasets/reanalysis-era5-single-levels?tab=overview) همچنین می‌گوید داده با حدود پنج روز تأخیر به‌روز می‌شود و انتشار اولیه ممکن است بعداً بازبینی شود. برای احتیاط در این آزمایش، اطلاعات دمایی را فقط تا **۷ روز قبل از تاریخ صدور** در دسترس فرض کردیم؛ این فرض باید هنگام اتصال به منبع زنده دوباره سنجیده شود.

## روش ارزیابی و جلوگیری از نشت اطلاعات

هر نمونه شامل `issue_date`، `target_date = issue_date + horizon` و آخرین تاریخ دادهٔ قابل دسترس `issue_date - 7 days` است. ویژگی‌ها فقط از آن تاریخ و قبل از آن ساخته می‌شوند: سه مقدار آخر، میانگین‌های ۷ و ۳۰ روز گذشته، شهر، افق و سینوس/کسینوس روز سالِ تاریخ هدف. مقدار واقعی روز هدف یا روزهای بین صدور و هدف وارد ویژگی‌ها نمی‌شود.

| مجموعه | شرط زمانی | تعداد جفتِ شهر/صدور/افق |
|---|---|---:|
| آموزش اولیه | هدف تا ۲۰۲۳-۱۲-۳۱ | ۲۱۱٬۴۲۵ |
| اعتبارسنجی | صدور از ۲۰۲۴-۰۱-۰۸، هدف تا ۲۰۲۴-۱۲-۳۱ | ۵۱٬۵۲۵ |
| آزمون نهایی | صدور از ۲۰۲۵-۰۱-۰۸، هدف تا ۲۰۲۵-۱۲-۳۱ | ۵۱٬۳۷۵ |

فاصلهٔ ابتدای هر سال تضمین می‌کند همهٔ برچسب‌های دورهٔ قبلی، با فرض تأخیر هفت‌روزه، هنگام اولین صدور دورهٔ بعد در دسترس بوده‌اند. مدل Ridge ابتدا فقط روی آموزش اولیه برازش و روی اعتبارسنجی سنجیده شد؛ سپس روی آموزش و اعتبارسنجی دوباره برازش و روی ۲۰۲۵ آزمون شد. میانگین‌سازی/مقیاس‌بندی فقط داخل Pipeline و روی دادهٔ برازش‌شده انجام می‌شود. ضریب Ridge از پیش ثابت (`alpha=100`) است؛ روی آزمون ۲۰۲۵ تنظیم نشده است. هر سه روش دقیقاً همان ردیف‌های آزمون را می‌بینند.

تعدادهای جدول بالا **پیش‌بینی‌ها** هستند، نه روزهای مستقل: یک روز هدف ممکن است با چند تاریخ صدور و افق متفاوت چند بار ارزیابی شود. بنابراین این تعداد نباید به‌عنوان تعداد مشاهدهٔ مستقل یا فاصلهٔ اطمینان تعبیر شود.

## نتیجهٔ آزمون نهایی ۲۰۲۵

در هر خانه، «MAE °C / درصد خطای حداکثر ±۲°C» آمده است. هر روش و هر هدف روی ۵۱٬۳۷۵ پیش‌بینی یکسان ارزیابی شده‌اند.

| روش | میانگین روزانه | کمینهٔ روزانه | بیشینهٔ روزانه |
|---|---:|---:|---:|
| ماندگاری | 4.0366 / 32.89٪ | 3.9668 / 33.37٪ | 4.7070 / 30.24٪ |
| آخرین روز هم‌نام هفته | 4.3048 / 30.77٪ | 4.2181 / 30.91٪ | 4.9374 / 29.07٪ |
| Ridge | **2.4311 / 50.21٪** | **2.4049 / 50.75٪** | **3.0370 / 41.62٪** |

Ridge در میانگین کل آزمون از دو مبنا بهتر بود. در ۵۱٬۳۷۵ خروجی آزمون Ridge هیچ موردی از `Min_C > Mean_C` یا `Mean_C > Max_C` دیده نشد؛ این یک مشاهدهٔ آزمون است، نه تضمین ساختاری برای آینده. نتیجهٔ جداگانهٔ هر شهر و هر افق در فایل JSON آمده است و ممکن است عملکرد افق‌های دور یا بعضی شهرها از میانگین کل ضعیف‌تر باشد.

برای نشان دادن اثر افق، MAE مدل Ridge در چند فاصلهٔ نمونه (میانگین پنج شهر، °C) چنین بود:

| فاصله تا تاریخ هدف | میانگین | کمینه | بیشینه |
|---:|---:|---:|---:|
| ۱ روز | 2.377 | 2.347 | 2.990 |
| ۷ روز | 2.312 | 2.347 | 2.917 |
| ۱۵ روز | 2.378 | 2.368 | 3.006 |
| ۳۰ روز | 2.610 | 2.508 | 3.191 |

این میانگین‌ها از نتایج شهرها برای همان افق محاسبه شده‌اند؛ جدول کامل JSON تعداد نمونه و هر دو معیار را برای همهٔ ۳۰ افق دارد.

**تفسیر درست:** این اعداد میزان توافق با سری ERA5 را نشان می‌دهند. چون مرجع آزمون بازتحلیل است، نمی‌توان از آن «دقت در برابر دماسنج‌های واقعی» یا «کیفیت پیش‌بینی زنده تا ۳۰ روز» نتیجه گرفت. هیچ مقایسه‌ای با خروجی زمان‌دار مدل هواشناسی عملیاتی انجام نشده است.

## بازتولید

از ریشهٔ مخزن و پس از نصب وابستگی‌های `requirements.txt`:

```bash
python -m scripts.build_era5_dataset --start 2020-01-01 --end 2025-12-31 --out data/era5_five_cities.csv
python -m forecasting.multi_horizon --data data/era5_five_cities.csv --out docs/ERA5_EVALUATION.json
python -m unittest discover -s tests -q
```

دستور اول به اینترنت نیاز دارد و ممکن است به‌علت بازبینی دادهٔ منبع، در اجرای آینده هش یا بعضی مقادیر متفاوتی تولید کند؛ فایل و فرادادهٔ ثبت‌شده، نسخهٔ دقیق این آزمایش‌اند. دستور دوم باید همان هش فراداده را ببیند. آزمون‌ها بدون اینترنت اجرا می‌شوند. بازاجرای دستور دوم با فایل ثبت‌شده، نتایج JSON را دوباره می‌سازد.

## کار باز و شرط انتشار

- پوشش و تعریف دادهٔ **مشاهده‌ای مستقل** برای هر پنج شهر هنوز تأیید نشده است. پیش از ادعای دقت واقعی باید یک مرجع ایستگاهی با مجوز روشن، نقص‌ها و کیفیت معلوم انتخاب و روی آن آزمون شود.
- خروجی عملیاتیِ صادرشده در گذشته باید با زمان صدور واقعی مقایسه شود؛ [آرشیو Previous Runs](https://open-meteo.com/en/docs/previous-runs-api) برای افق‌های ثابت ۱ تا ۷ روز یک گزینهٔ بررسی است. برای افق‌های طولانی‌تر، دسترسی به آرشیو مناسب و مقدار عدم‌قطعیت باید جداگانه مشخص شود.
- برای رابط کاربری آینده، منبع تازه، زمان دریافت، تاریخ صدور، افق، واحد، دامنهٔ اعتبار و محدودیت ارزیابی باید کنار پیش‌بینی نمایش داده شوند. تا آن زمان، برنامهٔ فعلی همچنان همان مسیر یک‌روزهٔ قدیمی است.
- معیار پذیرش محصول باید بر حسب شهر، هدف و افق پیش از دیدن آزمون مستقل بعدی تعیین شود؛ تنها میانگین کلی کافی نیست.

**جمع‌بندی تصمیم:** مسیر دادهٔ سه‌هدفه و ارزیابی ۱ تا ۳۰ روز قابل بازتولید شده است. انتشار ادعای دقت کم‌خطا یا ارائهٔ آن به‌عنوان پیش‌بینی عملیاتی هنوز توصیه نمی‌شود.
